# Universal Research App — v0.1.1 Release

**Release date:** 2026-08-29
**Status:** Released

---

## What was implemented

### Skill
- `research/SKILL.md` — Universal Research Skill v0.1.1, a portable behavioral specification enforcing:
  - Question-first reasoning
  - Evidence-before-conclusion
  - Fact vs Inference distinction
  - Contradiction handling
  - Confirmation-bias resistance
  - No fabrication
  - Traceable claims (source must directly support the specific claim)
  - Final quality check before output
  - Research provenance
  - Adaptive stopping criteria

### Application
- `research-app/app.py` — Streamlit web application:
  - Loads canonical `SKILL.md` from `research/SKILL.md` (one level up, never copied)
  - Injects skill as `system_instruction` into every Gemini API call
  - Enables Google Search grounding (`google_search` tool)
  - Auto model fallback: tries `gemini-3.6-flash` → `gemini-2.5-flash` → `gemini-2.5-pro` in order
  - Falls back to no-search mode if all grounding-capable models fail
  - Minimal, aesthetic UI (no clutter, no emoji, dark text on white)
  - Analysis Depth selector: Quick Summary / Standard / Deep Dive
  - Download report as Markdown
  - Shows which model produced the result

### Engineering
- Single canonical skill source: `research/SKILL.md`
- `research-app/SKILL.md` removed from git; added to `.gitignore` to prevent drift
- Smoke test suite: `research-app/test_smoke.py` (13 tests)
- Architecture audit: `research-app/ARCHITECTURE_AUDIT.md`
- Deployed on Streamlit Community Cloud with secrets-based API key management

## Architecture

```
research/
├── SKILL.md                        ← Canonical skill (single source of truth)
└── research-app/
    ├── app.py                      ← Streamlit application
    ├── test_smoke.py               ← Smoke test suite
    ├── ARCHITECTURE_AUDIT.md       ← Research capability audit
    ├── V0.1.1_RELEASE.md           ← This file
    ├── requirements.txt            ← streamlit, google-genai, python-dotenv
    ├── .env.example
    ├── .gitignore                  ← Blocks SKILL.md copy, .env, venv/
    └── .streamlit/
        └── config.toml             ← Minimal UI theme
```

**Execution path:**
```
User submits question
  → app.py :: main()
     → get_skill_content() reads ../SKILL.md
     → run_research(client, skill_content, prompt)
        → GenerateContentConfig(system_instruction=skill_content, tools=[google_search])
        → Gemini API (server-side search grounding)
     → Structured report rendered
     → Download button (.md export)
```

## Known limitations

### 1. Source verification is snippet-level only
The `google_search` grounding tool provides search snippets (~1–3 sentences per source), not full page content. The model cannot independently navigate to URLs or read full articles. The SKILL.md requirement "verify the source's content actually supports the claim" is satisfied at snippet level, not full-content level.

This is a structural constraint of the Gemini grounding API, not a code defect.

### 2. Model availability depends on API key tier
Model names in the Gemini API change frequently. The fallback list may need updating as models are deprecated. Free-tier API keys may hit rate limits (~15 req/min) during heavy use.

### 3. No session persistence
Research results are not stored between sessions. Each page reload starts fresh.

### 4. No export formats beyond Markdown
The download button produces `.md` only. PDF, HTML, and Word export are not implemented.

## What is intentionally NOT implemented

| Feature | Reason |
|---|---|
| Full-page URL fetching | Would add complexity and failure modes without guaranteed improvement for most queries |
| Tavily / SerpAPI / external retrieval | Out of scope for v0.1.1 proof-of-concept |
| Vector database / RAG | Architecture decision: grounding sufficient for PoC |
| Academic database integration | v0.2 candidate |
| Session history / persistence | Unnecessary for PoC |
| PDF / HTML export | Not requested |
| User authentication | Not required for personal tool |
| Multiple simultaneous research threads | Not in scope |

## Recommended future upgrade triggers

Move to v0.2 when:

1. **Specific failure case**: A research query produces a conclusion that is demonstrably wrong because snippet-level grounding was insufficient and full-page content would have corrected it.

2. **Academic research use case**: The tool is used for literature reviews, systematic reviews, or academic citation where verified full-text access is required.

3. **Production deployment**: Moving from personal proof-of-concept to a team tool or public research service.

4. **Repeated model deprecation**: If the Gemini model list continues to change rapidly, consider adding a `/models` endpoint call at startup to discover available models dynamically.

**Upgrade path:**
The architecture is clean for v0.2. Only `run_research()` in `app.py` needs modification to add an external retrieval layer. `SKILL.md` remains unchanged.
